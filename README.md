# Лабораторная работа 3 · Crypto Dashboard

Настольное приложение на Java 17 и Swing. В списке справа можно выбрать Bitcoin, Ethereum или Solana. Карточки обновляются до закрытия окна. Для получения данных нужен доступ к интернету.

## Запуск

В IntelliJ IDEA откройте файл `lab3/pom.xml` как проект Maven, выберите JDK 17 или новее и дождитесь загрузки зависимости Gson. Откройте класс `lab.Dashboard` и запустите метод `main`.

Если Maven установлен в системе, из корня репозитория выполните

```powershell
cd lab3
mvn compile exec:java
```

## Как устроено обновление

| Источник | Данные | Когда обновляется |
| --- | --- | --- |
| [Kraken](https://docs.kraken.com/api/docs/websocket-v2/ticker/) | Цена последней сделки в USD | При подписке и после новых сделок через WebSocket |
| [Coinbase](https://docs.cdp.coinbase.com/api-reference/exchange-api/rest-api/products/get-product-stats) | Минимум и максимум цены за 24 часа в USD | Сразу и через 30 секунд после успешного ответа |
| [CoinPaprika](https://docs.coinpaprika.com/api-reference/coins/get-coin-by-id) | Название, тикер и место в рейтинге | Сразу и через 5 минут после успешного ответа |

`Dashboard` создаёт окно и обрабатывает выбор монеты. `Session.start()` запускает подписку через `buildAsync` и два отдельных запроса через `sendAsync`. У каждого HTTP-запроса есть собственный обработчик завершения. Он обновляет свою карточку в потоке событий Swing и планирует следующий запрос.

При ошибке HTTP карточка сохраняет последнее полученное значение, показывает причину и повторяет запрос через 30 секунд. При обрыве WebSocket приложение заново подключается и подписывается на выбранную пару. Задержка между попытками растёт от 2 до 30 секунд и сбрасывается при получении котировки.

При смене монеты или закрытии окна `Session.stop()` отключает прежний поток, останавливает таймеры и отменяет незавершённые запросы. Обработчики проверяют, активна ли ещё их сессия, чтобы запоздавший ответ по Bitcoin не появился на экране Ethereum.
